## memory-qq-2026-10-09.diff

### 为什么需要它

拼进提示词的【对群友的全局印象】原本只写昵称。昵称是不可靠的标识：同一个群里的昵称可能
重名、可能是英文缩写，也可能本身就是一句会误导的话（读起来像系统消息或事件）。模型据此
认人，就会出现"把 A 的印象算到 B 头上"这类问题。

QQ 号是稳定且唯一的，而系统其它部分（人物档案、记忆文件、身份来源表、以及所有"对某个人
动手"的工具参数）本来就以 QQ 号为主键——只有**显示给模型看的那一层**用的是昵称。这个补丁
把显示层也带上号，让两边对得上。

管理员那一行保持原有形态（`（QQ …，就是管理员本人）`），因为那句"就是管理员本人"是模型
判断"谁在管这个账号"的依据。若某个人还没有昵称、显示的就是号本身，则不重复拼接。

### 打补丁

在服务器上、以 `app/` 为当前目录执行：

```bash
cd /mnt/data/qq-agent/app
patch -p1 < patches/memory-qq-2026-10-09.diff      # 路径按实际存放位置替换
./.runtime/node-v22.23.2-linux-x64/bin/node --check src/memory/memory-global.js
systemctl --user restart qq-agent-linux
```

- `node --check` 通过只是语法通过；真正生效要重启服务（Node 不热加载源码）。
- 改的是**展示层文案**，不改变任何发送行为与数据。

### 验证

1. 补丁与线上文件是否一致：`patch -p1 --dry-run -R < memory-qq-2026-10-09.diff`
   反向 dry-run 通过，说明该补丁与当前文件逐字吻合。
2. 效果：重启后，运行时拼出的【对群友的全局印象】每行形如
   `- 昵称(QQ 123456)：[09-22] …`；管理员那行仍是 `昵称（QQ 123456，就是管理员本人）`。

### 回退

```bash
patch -p1 -R < memory-qq-2026-10-09.diff
systemctl --user restart qq-agent-linux
```

服务器上另有改前的原件副本（`memory-global.js.bak-<日期>`），便于直接比对。

### 维护注意（对本目录所有补丁通用）

- 上游若改过同一个文件，`patch` 会报 `hunk failed`——**不要硬打**（`--forward` 会留下半个
  改动），照新版本的代码手工重做，再重新生成补丁文件。
- 补丁针对的是 v0.8.1 的行号；跨版本打之前先 `diff` 一眼上下文是否还对得上。
- 打完记得 `node --check` 目标文件，并重启服务（Node 不热加载源码）。

## sticker-collect-criteria-2026-10-10.diff

### 为什么

表情自动收藏原先的判定标准只有一条——「以后聊天时用得上吗」，而且"值得收"里明确写着
**带字的梗图、抽象搞笑图**。结果是不分画风地收：社交平台常见的网红卡通形象梗图、截图式
梗图都进了表情库，跟角色（一个二次元高中生）的形象不搭。

### 改了什么

- 判定标准改成**两条都要过**：① 以后聊天时用得上；② 跟二次元高中生的形象搭。
- 「值得收」删掉"带字的梗图"这种一刀切说法，改为：ACG／动漫画风角色图、动漫梗图、番剧或
  动画截图（带字幕、台词、梗的也算）、可爱或干净的卡通形象、抽象但不出戏的搞笑图、猫猫狗狗。
- 「不值得收」补三类：跟形象不搭的**社交平台网红卡通形象梗图**、真人/三次元梗图、带平台或
  账号水印或整屏截图的图；另加新闻等无关截图与擦边重口味。
- 一律按**特征**描述、不点名具体 IP —— 点名容易被读成对某个作品的贬损，能不惹这个麻烦就不惹。
- **同时把判定标准做成配置项** `sticker.collectCriteria`：只写"收什么 / 不收什么"，身份那句
  （你是「谁」、正在看谁的图）仍由代码补在前面。留空 = 用内置默认；填了 = 用配置的
  （上限 2000 字，防撑爆判定请求）。

做成配置的原因：这段文字会随角色形象反复微调。走配置改一句话**即时生效，不用改代码、
不用重启**——以后微调不必再动这个补丁。

### 怎么调

用控制台接口写一个字符串即可（身份那句不用写，只写标准）：

```
POST /api/config
{"sticker":{"collectCriteria":"判断标准：……值得收：……不值得收：……"}}
```

清空（`"collectCriteria": ""`）就回到内置默认。

**本部署当前就用内置默认**（`collectCriteria` 留空）——默认那套已经包含"放行动漫／番剧截图
（带台词、梗的也算）、挡掉新闻与平台整屏截图"。想再调，按上面的方式填一段即可。

### 效果实测（2026-10-10，同一批真实群图）

| 图 | 判定 | 理由（模型原话） |
|---|---|---|
| 番剧截图带台词 | **收下** | "番剧截图带台词，画风干净，心虚偷看梗聊天常用" |
| 抽象卡通 + 文字梗图 | **收下** | "干净可爱的卡通形象+文字梗，接梗吐槽都能用，符合形象" |
| 新闻文字截图 | **不收** | "纯文字科技新闻截图，非表情包，聊天用不上也不搭形象" |

配置路径也单独验过：把 `collectCriteria` 临时设成"一律不收，reason 必须以 TEST-REJECT 开头"，
模型返回的理由就是 `TEST-REJECT …`，随后已清空恢复默认。

### 注意

这是**提示词级的判断**，不是硬过滤器——模型偶尔仍可能收错。想确认它是否按新标准在拒，
看日志里的 `[sticker] 判断：… —— <理由>` 就行。
